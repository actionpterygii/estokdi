# チーム・部門データの更新

このSkillは、チーム・部門データの追加、更新、削除を扱います。依頼された範囲に合わせて作業し、関係のないチームや部門を変更しません。

## 作業の種類

依頼を次の作業に分類します。複数の作業が含まれる場合は、必要なものを組み合わせます。

1. **既存チームの部門を追加・削除**：チームの `divisions` を更新します。ゲームタイトル自体の新設・廃止を伴わないメンバーシップ変更です。
2. **既存部門の情報を更新**：既存チームにある部門の公式ページURLや、利用可能な部門固有情報を更新します。
3. **チームの部門以外の情報を追加・更新・削除**：チーム名、読み、会社、SNS、ショップ、ハッシュタグなど、依頼された項目を更新します。
4. **新規部門を追加**：ゲームタイトルを部門一覧に登録し、その部門を持つ既存チームにも登録します。
5. **部門を掲載終了**：掲載中チームからその部門を削除し、`delete_division.json` の既存形式に従って保管します。
6. **新規チームを追加**：チームデータと必要なロゴを追加し、対象となる部門や関連リンクを登録します。
7. **チームを掲載終了**：掲載中一覧からチームを削除し、`delete_team.json` の既存形式に従ってチームデータを保管します。

掲載終了と完全削除を区別します。ユーザーが完全削除を明示した場合は保管せず削除します。明示がない場合は、既存の削除データの扱いに合わせて保管します。

## 変更するデータと関連ファイル

- 掲載中のチーム情報は `src/json/teams.json` にあります。
- 部門のID・表示名は `src/json/divisions.json` にあります。チーム側の `divisions[].name` は部門の `id` と一致させます。
- Liquipediaのカテゴリ対応は `src/json/liquipedia_divisions.json` にあります。対象部門のLiquipediaリンクを掲載する場合に、必要な対応を更新します。
- 新しいデータ項目やリンク・部門種別を加える場合は、`team_sample.json` も実データと一致するよう更新します。
- チームロゴは `public/img/team/{チームID}.webp`、部門ロゴは `public/img/division/{部門ID}.webp` です。新しい項目に必要な画像があるか確認します。
- リンク種別を新設する場合は `public/img/link/{リンク名}.webp` と表示側の対応も確認します。
- 画面表示の仕様変更を伴わないデータ更新では、通常 `src/pages/` や `src/components/` を変更しません。

## 情報の確認と更新

- チーム・部門の公式サイトや公式SNSなど、一次情報を優先して名称、活動状況、リンク先を確認します。裏付けが取れない情報を推測で追加せず、不明点が作業を左右する場合はユーザーに確認します。
- 既存の `id` は変更しません。新しいIDは重複を避け、リポジトリ内の命名に合わせます。
- 既存のJSON構造・順序・書式を保ちます。`links[].urls` などに複数URLがある場合や、`vlr_ggs`、部門ごとの `liquipedia_id` などの任意項目を不用意に削除しません。
- 新規部門では、その部門を持つと確認できたチームだけに登録します。新規チームでは、依頼された範囲で確認できた部門のみ登録します。
- 部門やチームの削除では、公開データから除く対象と、削除データとして保管する内容を照合します。

## 公開用ファイルの更新

Astroソースの変更を公開用 `docs/` に反映する依頼では、`npm run build:pages` を実行します。これはビルド後に `dist/` の内容を `docs/` へコピーし、同名ファイルを上書きします。`docs/` にだけあるファイルは削除しません。

反映後は、生成されたチーム・部門ページが変更内容と一致すること、必要な画像やリンクが含まれていることを確認します。更新日を変更する依頼では、`src/components/Footer.astro` と `astro.config.mjs` の日付も揃えます。
